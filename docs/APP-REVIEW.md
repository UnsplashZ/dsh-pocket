## 二、发现的问题

### 1. 死代码（不影响功能，但该清）

| 位置 | 说明 |
|---|---|
| `DSHClient.statFile` | 定义了没接上（文件预览用的是 `readFile`） |
| `DSHClient.listProjections` | 被 `sessionProjections` 取代 |
| `DSHClient.events` | 早期 `$events` 方案残留，被 mux 取代 |
| `DSHClient.commands` | 返回原始 JSON 的旧版，被 `listCommands` 取代 |
| `TodoCard`（`TimelineRow.swift`） | 待办挪到输入框上方后不再使用 |

### 2. 界面空态缺引导

这几处在"没有数据"时只是不显示，用户不知道是"没有"还是"坏了"：

- **待办面板**：`todos` 投影为空时整块消失（符合预期，但没有"这一步没有待办"的暗示）
- **后台任务面板**：有 `ContentUnavailableView` ✓
- **定时提醒页**：有 `ContentUnavailableView` ✓

### 3. `@` 引用的实现方式（已确认可行）

`PromptContentPart` 只有 `text | image | file` 三种 —— **没有结构化的引用块**。
所以 `@path` 就是**纯文本**，靠宿主注入的 `FILE_REFERENCE_PROMPT`
（`dsh-file-reference-local`）教模型自己解析。

**结论：我的实现方式是对的**，跟桌面端一致。

### 4. 已知但未修

- 切换权限会在时间线留下 `⌘ permission` 那几行 note
  （机器通知那条已过滤，命令本身的 note 还在）
- 计时器起点在"有界快照切掉这一轮开头"时会比电脑短一点
  （主机没有提供"这一轮从何时开始"的字段）

## 三、测试覆盖的薄弱处

- **`SessionModel` 几乎没有单元测试** —— 它是最大的一个类（900+ 行），
  但所有逻辑都跟 `DSHClient` 绑死，没法脱离网络测。
  最近几个 bug（队列、计时器、空白）全都出在这里，而且**都是靠用户复现才发现的**。
- 建议：把"队列合并"、"计时器起点"、"折叠后滚动"这几处抽成纯函数放进 DSHKit，
  就能像 `TimelineBuilder` 那样测。
